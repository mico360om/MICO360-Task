# Android App 1.19 — Stage 3 (Planning and AI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real Timeline, Workload, Management and MICO AI screens in the Android app, plus the calendar's waiting-for-approval hourglass, so that a phone user plans, checks the company and asks MICO AI as on the website 1.19. These screens replace Stage 1's "opens on the website" rows and Search entries. Templates stays a website link until Stage 4.

**Architecture:** One lead task registers the four routes in the menu, Search and App Links, with temporary shells. Three parallel lanes then fill them: Planning (Timeline, Workload, calendar), Management, and MICO AI. A last lead task merges the lanes and removes the shells' website fallbacks.

Each area has the same layers:
- `lib/<area>-api.ts`: the server's types and requests, unwrapped from `{ data }`.
- `lib/<area>.ts`: a behaviour copy of the website's rules, drift-tested by running the website's own module on the same fixtures.
- `core/<area>-queries.ts`: hooks. Every key carries the user id, every request sends `asUser`, and nothing goes into the offline copy.
- The screen and its components, tested by source text (vitest runs without React Native).

The app never recounts a number the server sends.

**Tech Stack:** Expo SDK 51 / React Native 0.74.5, React Navigation 6, TanStack Query 5, vitest 2 + esbuild, TypeScript 5.5. No new packages: charts use the app's `components/charts.tsx`, downloads use `lib/exporter.ts` `exportFile`, Copy uses `adapters/clipboard.ts` `copyText`.

**Spec:** `docs/superpowers/specs/2026-10-31-android-app-parity-1-19-design.md` §3 "Stage 3", §4 anti-goals and §7 ("phone layouts copy the website's own phone layouts where it has them (Timeline list…); where it has none (Workload, Management), a phone design in the same style"; "MICO AI polls for answers like the website"), plus `…-gap.md`. Base plan: `docs/superpowers/plans/2026-10-31-android-1-19-stage1.md`. Its names are consumed exactly as its tasks' **Produces** give them.

**Tests and copies of website logic**
- vitest runs `src/**/*.test.ts` in Node without React Native. Logic lives in `src/lib/*.ts` and is unit-tested. Components and screens are tested by reading their source (`src(rel)` = Stage 1's `appSource`).
- **Behaviour copies.** An app file named after a website `lib/` file exports the website's names and returns the same output. It may differ in how it builds dates (day-words), and it never uses glyphs. Its drift test loads the website module with `loadWebTs(rel, imports)` and compares outputs on the shared fixtures under `describe.skipIf(!hasWeb(…))`.
- Words that live in a website component get a text drift test: `expect(readWeb(file)).toContain(<the app's text>)`.
- Fixtures live in `src/testing/*-fixtures.ts`. The style guard and the date scans leave `src/testing/**` out.

**Rules for runtime code**
- Dates and times only through `lib/day-words` (`dayText`, `clockText`, `instantDayText`, `dateTimeText`, `dayKeyIn`). Stage 1's `date-locale.test.ts` scans every new file: no `month:`/`weekday:` options, no `toLocale…String`.
- Query strings are built by hand with `encodeURIComponent`, **never `URLSearchParams`** (React Native's has no `get`/`set`).
- No `\p{…}` regex.
- No style-guard glyph in a runtime string. The website's "◆" and "✓" become the drawn icons `misc.milestone` and `misc.check`.
- No colour literal, no `fontWeight`, no `<Loader` in `screens/**`. Initials only through `<Avatar>`. Colours only from `lib/theme.ts` tokens. Text uses the text tones; status fills are only for bars and dots.

**Data isolation**
- Every Stage 3 query key is `[<root>, userId, …]`, with root `'planning'`, `'management'` or `'mico-ai'`.
- Every Stage 3 request passes `asUser: userId`.
- No Stage 3 hook uses the offline copy (`reads.read`) or the offline queue (`queueOnOffline`/`sync`).
- Sign-out's `clearQueryCache` (Stage 1) drops it all.

## Review Focus

1. **Shared phone, Management.** An admin opens Management, signs out, and an employee who runs no project signs in and follows a `/management` link. The employee never sees the screen's figures, not even for a moment.
   - Access and figures are keyed by the user id.
   - The overview is not asked for until the server says yes.
   - A 403 turns the screen into "no longer" and removes the figures from memory.
   - Owning test: Task 7, `management-gate.test.ts`.
2. **MICO AI across background and sign-out.**
   - An answer still being written while the app goes to the background is not polled in the background. It is read once as soon as the app is back, and polling stops when the answer is done.
   - After a sign-out and someone else's sign-in, nothing of the first person's chats can show: keys carry the user id, requests carry `asUser`, and nothing is in the offline copy.
   - Owning tests: Task 12, `mico-ai-chat.test.ts` and `mico-ai-queries.test.ts`.
3. **Confirm twice.** A double tap on Confirm, or a Confirm whose answer was lost and is tapped again, applies the changes once.
   - A per-card gate lets one action run at a time.
   - An action whose answer was lost is never re-sent: the card is read again.
   - The buttons follow the card's status (`confirming` shows none).
   - Owning tests: Task 12, `createActionGate`; Task 14, `cardControls`.
4. **Workload suggestion on an old copy of a task.** The suggestion is sent with the version shown. The server's 409 (VERSION_CONFLICT / TASK_DONE / ASSIGNEE_GONE) is said in the website's plain words, the numbers are read again, and nothing is queued for later.
   - Owning test: Task 4, `workload.test.ts` "a suggestion made on an old copy…".
5. **Numbers equal the server's.** Timeline progress, health, days late and each task's overdue, and Workload's count, limit, over, total, week limit and overdue, are shown as sent. Fixtures deliberately disagree with what a recount would give.
   - Only the website's own sums are added up (the five Timeline cards, `summaryLine`, "+ N more").
   - Owning tests: Task 2, `timelineRow`; Task 4, `popoverTasks`; Task 3 and Task 5 screen tests.
6. **A link never asks MICO AI anything.** A link such as `https://task.mico360.com/mico-ai?ask=…&askId=…` from an email or web page opens MICO AI without asking a question as the person. Only Search sets `ask`.
   - Owning test: Task 1, `stage3-routes.test.ts`.
7. **Dark mode and badges.** Every Stage 3 pill, chip and day cell uses a colour pair that Stage 1's `contrast.test.ts` already checks (`toneStyle` pairs, `ink2` on `surface2`).
   - Owning tests: Task 2 and Task 4, `planning-look.test.ts`.
