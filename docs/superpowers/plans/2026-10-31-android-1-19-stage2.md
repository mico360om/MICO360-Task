# Android App 1.19 — Stage 2 (Daily Work) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the Android app the website 1.19's daily work: approvals (tick, Approve / Send back, To approve, Dashboard card, switches), moving a task to another project, the website's Dashboard and Projects pages, the task screen's phone order and marks, New task's checklist / due-today note / templates, board chips, the Meetings page patterns, and the Settings / Users / Reports leftovers.

**Architecture:** Built on Stage 1 (merged into `feat/android-1-19`). Task 1 adds every new API type, resource, icon and the one shared read hook up front, so three lanes can then work in three worktrees without touching the same files: Lane A the task work (task screen, form, approvals on a task, move, boards), Lane B the Dashboard and Projects pages, Lane C Meetings, Settings, Users and Reports. Website logic is copied into `src/lib/*.ts` with drift tests; screens are checked by source text; cache logic that must survive offline/online lives in plain functions that take a `QueryClient` so vitest can run it.

**Tech Stack:** Expo SDK 51, React Native 0.74.5, React Navigation 6, TanStack Query 5, vitest 2 + esbuild; Stage 1's `components/ui/*`, `Icon`, `lib/day-words.ts`, `lib/approvals.ts`. No new packages.

**Spec:** `docs/superpowers/specs/2026-10-31-android-app-parity-1-19-design.md` §3 "Stage 2" and `…-1-19-gap.md` (same folder). Stage 1 plan: `docs/superpowers/plans/2026-10-31-android-1-19-stage1.md` — this plan consumes its Produces blocks by name.

## Review Focus

1. A non-manager on a task, or making one in a project that asks for approval: "Needs approval" is shown on and disabled with "Only the project’s managers can turn this off."; if the server still refuses (rights changed meanwhile) its own words "Only the project’s managers can turn off approval for this task." show — never "You don’t have permission to do that." or a silent revert → Task 3 (`approvalView`, refusal test), Task 5 (`approvalTickFor`, `saveTaskEdit` refusal test).
2. Send back with an empty or spaces-only reason → "Write a reason first." and nothing sent; the reason is sent trimmed; 2000 characters is the most (the box stops there; anything longer → "Keep the reason under 2000 characters.") → Task 3 `sendBackCheck`.
3. Moving one or several tasks whose assignees aren't on the new team → one question for the whole group ("Add them to the team" / "Unassign them"); no answer → "Choose whether to add them to the team or unassign them."; the server's 409 asks again with a fresh preview; afterwards the old key ("RIG-4") still opens the task, whose header says "Formerly RIG-4" → Task 7.
4. Dashboard numbers: an administrator's All tasks and Overdue are the sums of the server's `/reports/projects`; an employee's Overdue is exactly the tasks the server's `isTaskLate` calls late (never one waiting for approval) and Due this week ends on the company's week end → Task 9.
5. Projects tab counts are `/projects/overview`'s list counted by the website's `tabCounts` (after the filters); a status change moves the project between counts at once, goes back with the offline sentence when there is no connection, and the list is read again from the server after a success → Task 10.
